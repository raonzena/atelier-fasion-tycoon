# ATELIER — 패션 회사 타이쿤

웹에서 바로 플레이하는 패션 회사 경영 게임입니다. Sites 작업 폴더에는 게임 정적 파일이 `dist/client/`, 배포용 Worker가 `dist/server/`에 있습니다. GitHub 저장소에는 게임 파일이 루트에 있습니다.

## 시작과 성장

- 처음 접속하면 회사명을 정합니다. 고객·직원·가구는 모두 0에서 시작하고 초기 자산은 ₩180M입니다.
- 왼쪽 메뉴에서 직원 고용, 가구 구매, 배치 수정, 팀·연구를 엽니다. 구매하거나 고용한 항목은 빈 칸에 먼저 놓입니다. 배치 수정에서 사무실 바닥의 서로 다른 좌우 기울기에 맞춘 격자를 보고 드래그하여 옮길 수 있습니다. 드래그 중 놓일 칸이 강조되고 오른쪽 아래 버튼으로 배치를 저장하거나 취소할 수 있습니다.
- 직원 최대 고용 수는 오피스 LV.1–3에서 레벨+1명(시작 정원 2명), LV.4–7에서 레벨+2명, LV.8–12에서 레벨+3명입니다(정원: 2, 3, 4, 6, 7, 8, 9, 11, 12, 13, 14, 15명). 가구 최대 보유·배치 수는 레벨별로 2–13개입니다. 후보 직원은 오피스 레벨에 맞춰 열립니다.
- 오피스 LV.1부터 LV.12까지 확장합니다. 후보 직원의 기본 능력치는 채용 해금 레벨(5 + 해금 레벨)에 직군별 특성 보정을 적용합니다. 베리와 코코는 각각 LV.9, LV.10에서 해금됩니다. 다음 사무실 확장에는 현재 오피스 레벨의 두 배만큼 컬렉션 출시 경험이 필요합니다(예: LV.1→2는 2회, LV.11→12는 22회). 회사 레벨도 12까지 올라가며 최대 레벨에는 `Max`로 표시합니다.
- 왼쪽 대출 관리 메뉴에서 회사 레벨별 한도 안에서 자금을 빌리고, 원하는 금액을 중간 상환하거나 전액 상환할 수 있습니다. LV.1 원금 한도는 ₩60M, 출시 월 이자율은 8.0%이며 회사 레벨마다 한도는 ₩40M 늘고 이자율은 0.5%p 낮아져 LV.12에서 ₩500M·2.5%가 됩니다. 대출 잔액은 원금과 미납 이자로 분리됩니다. 컬렉션을 출시할 때 당시 회사 레벨의 이자가 남은 원금에만 붙고, 상환은 이자를 먼저 갚습니다. 대출과 상환 내역은 기기 저장을 켠 경우 함께 저장됩니다.
- 대출이 남아 있을 때는 오른쪽 사무실 정보 아래에 총 상환액·현재 월 이자율·상환 버튼이 나타납니다. 상환 버튼은 대출 관리 화면의 중간 상환 입력으로 이동합니다.
- 디자인·생산·마케팅 직군에 서로 다른 털무늬와 작업 소품을 가진 고양이 직원이 각각 3명씩 더 있습니다. 직원 고용과 가구 구매 목록은 페이지당 5개씩 표시되며 잠긴 항목에는 자물쇠와 해금 레벨을 보여줍니다.
- 직원에게 디자인·봉제·트렌드 감각·생산 효율 네 능력치가 있습니다. 디자이너는 디자인, 생산 직원은 봉제·생산 효율, 마케팅 직원은 트렌드 감각이 강합니다. 프로필에서 각 능력의 기본값·레벨 보너스·현재값과 경험치를 볼 수 있습니다. 레벨별 증가량은 항목 기본값을 8로 나눈 뒤 반올림해 최소 1로 계산합니다(기본 8이면 레벨마다 +1, 기본 16이면 +2). 기존 저장 데이터도 현재 직군·레벨에서 네 능력을 계산합니다. 사무실 배치에 따른 제작 보너스는 적용하지 않습니다.
- 사무실 화면 왼쪽 위 메뉴에서 관리 기능을 열고, 오른쪽 위에서 회사 레벨·자산·고객과 간단한 오피스·시즌 정보를 봅니다. 오피스 레벨 옆 정보 버튼은 수용 인원·출시 현황·확장 조건을 보여주며, 그 화면에서 확장합니다. 오른쪽 아래 발바닥 버튼으로 새 컬렉션을 만듭니다. 전체 UI는 연한 핑크·노랑·크림 테마를 사용합니다.

## 컬렉션

- 의류 5종, 스타일 5종과 고객·소재를 조합하고 고용한 직원을 제작에 배정
- 제작에 배정된 각 직원의 네 능력마다 20–100% 범위에서 무작위 결과를 굴린 뒤 항목별로 합산합니다. 디자인·봉제 각 30%, 트렌드 감각·생산 효율 각 20%로 합산한 결과가 시즌 일치와 소재 보너스를 반영한 성공 목표 이상이면 성공합니다. 예상 성공률은 고정 난수로 384회 미리 계산한 추정값이며 실제 출시 때 새로 굴립니다. 출시 매출·고객·리뷰 리포트에 항목별 결과와 성공 목표를 표시합니다.
- 제작 중 진행도와 함께 네 능력의 무작위 결과가 각각 올라가고 고양이들이 열심히 일하는 별도 사무실 삽화가 은은하게 움직입니다. 참여 직원 초상화와는 분리된 연출입니다. 예상 성공률은 별도로 표시하며 성공 결과의 진행도는 100%까지 채웁니다. 출시 성공 시 폭죽, 실패 시 실망한 팀 이미지가 표시되며 결과 리포트에 자산·고객·연구 포인트의 실제 증감과 증감률을 화살표로 보여줍니다. 참여 직원은 출시마다 경험치 1을 얻습니다.
- 컬렉션 결과 화면에서는 매출·리뷰·능력 합산·증감·획득 경험치를 확인합니다. 회사나 참여 직원이 레벨업했다면 결과 화면의 사무실 복귀 버튼 또는 닫기 버튼을 누를 때 레벨업 정보 모달이 이어서 열리고, 이를 닫으면 사무실로 돌아갑니다.
- 첫 화면은 1년차 1월(겨울)이며 출시마다 한 달 진행합니다. 봄은 3~5월, 여름은 6~8월, 가을은 9~11월, 겨울은 12~2월입니다. 과거 3월 시작 저장 데이터는 날짜와 진행 중인 연구의 남은 기간을 유지해 이관합니다.
- 4개월마다 패션위크 참가를 선택합니다. 참가하지 않으면 일반 컬렉션을 만듭니다. 참가하면 고양이 런웨이 행사장으로 장면이 바뀌고, 실제 제작에서 굴린 디자인·봉제 30%, 트렌드 감각·생산 효율 20%를 합산해 다른 랜덤 브랜드와 겨룹니다. 경쟁 브랜드가 채우는 1~3위에 들면 각각 ₩3,000M·₩1,000M·₩500M을 받으며, 최소 14점 미만은 입상하지 못합니다. 순위·상금과 경쟁 브랜드는 결과 리포트에 표시합니다.
- 2회 출시 시 후드티, 5회 출시 시 가방 발견; 연구 포인트로 리넨과 재생 원단 해금
- 오피스 레벨 1–12: 작은 방과 3×3 배치 격자에서 시작해 사무실 그림과 함께 최대 8×8까지 확장, 레벨 4·8에 사무실 배경 전환. 상위 단계는 대리석 바닥
- 첫 사무실 그림의 폭을 장면의 58%로 줄이고 최고 레벨까지 점차 100%로 키웁니다. 오피스 확장 완료 화면에는 폭죽과 직원·가구 정원, 배치 칸, 새 사무실 배경 등 실제 변경 항목을 표시하고 숫자를 올려 보여줍니다. 컬렉션 출시로 회사 레벨이 오르면 별도 모달에 대출 한도와 월 이자율 변화를 보여줍니다. 직원이 레벨업하면 각 능력치의 이전값과 상승값을 표시합니다.
- 사무실 그림이 확대되어도 직원·가구 이미지와 배치 클릭 영역은 화면에서 비슷한 크기를 유지하도록 사무실 크기에 역비례해 조정합니다.

게스트 플레이는 새로고침 시 초기화됩니다. 선택하면 이 브라우저의 기기에 저장할 수 있습니다. Firebase 프로젝트의 이메일·비밀번호 계정으로 로그인하고 Firestore에 진행 내용을 저장합니다. Google 로그인은 제공자 설정과 지원 이메일 확인 후 활성화할 수 있습니다. 기기 저장과 계정 저장이 다르면 어느 진행 내용을 사용할지 먼저 선택할 수 있습니다. 저장 중 네트워크 오류가 나면 계정별 임시 사본을 이 브라우저에 두고 다시 로그인할 때 복구합니다. Android MVP는 배포된 웹 게임을 WebView로 엽니다. Sites 배포와 GitHub 저장소는 자동 동기화되지 않습니다.

## Firebase 연결

1. `atelier-fasion-tycoon` 프로젝트의 웹 앱을 등록하고 Authentication의 **이메일/비밀번호**를 사용 설정했습니다. Google 제공자는 지원 이메일 공개 여부를 확인한 후 켜고 Sites의 `FIREBASE_WEB_CONFIG` 런타임 값에서 `googleEnabled`를 `true`로 바꿉니다.
2. Authentication의 **승인된 도메인**에 `atelier-fashion-tycoon.sulhwa-dev.chatgpt.site`를 추가했습니다. 로컬 시험용 `localhost`도 기본 등록돼 있습니다.
3. 서울 리전의 Cloud Firestore 기본 데이터베이스를 생성하고 `firestore.rules` 내용을 Firestore **규칙** 탭에 게시했습니다.
4. Firebase 웹 구성값은 저장소 파일에 두지 않습니다. Sites의 `FIREBASE_WEB_CONFIG` 런타임 값으로 보관하며 Worker의 `/api/firebase-config`가 브라우저에 필요한 공개 구성값만 전달합니다. 서비스 계정 키는 사용하지 않습니다.

설정값을 불러올 수 없는 경우에도 게스트 플레이와 기기 저장은 계속 작동합니다. Firebase 웹 구성값은 브라우저 SDK 작동에 필요한 공개 정보이므로 런타임 응답에는 표시됩니다. 실제 게임 데이터 접근 권한은 Firestore 규칙이 제한합니다. Firestore 경로는 `saves/{Firebase UID}`이며 로그인한 본인만 읽고 쓸 수 있도록 규칙을 제한합니다. 게임 규칙과 자산 계산은 여전히 클라이언트에서 실행하므로 순위표나 실제 결제 보상을 도입한다면 서버 측 검증이 별도로 필요합니다.

모바일 회사명 입력 후에는 키보드를 닫고 화면 스크롤을 맨 위로 되돌려 사무실 상단에서 시작합니다.

사무실 기본 배경은 첫 화면에서 우선 로딩하고, 다음 사무실 배경과 실패 연출은 브라우저 여유 시간에 미리 받습니다. 이미지 에셋은 서비스 워커가 사용 시 저장해 재방문에 재활용합니다. 게임 로직과 페이지는 캐시 대상에서 제외해 업데이트가 오래 남지 않도록 했습니다.
사무실 배경과 직원·가구·제작 삽화는 아직 다운로드 중이면 해당 이미지 영역에 은은한 스켈레톤을 표시하고, 로딩이 끝나면 제거합니다.
